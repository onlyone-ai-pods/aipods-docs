Spec-Driven Development · Automatización ARCA/AFIP con Playwright · Versión 2026-07

⚠ Seguridad Las claves fiscales se almacenan en cuits.json en texto plano y están excluidas del repositorio vía .gitignore. Ningún selector, esquema ni escenario de este informe contiene CUIT ni contraseñas reales.

1. Historias de Usuario (User Stories)

US-01Descarga de Comprobantes Emitidos y Recibidos
Como consultor contable,
quiero que el sistema navegue automáticamente al servicio "Mis Comprobantes" de ARCA, aplique un rango de fechas personalizado y descargue las facturas emitidas y/o recibidas en formato Excel o CSV,
para tener los comprobantes del período en mi carpeta local sin ingresar manualmente al portal.
US-02Descarga de Retenciones y Percepciones (SICORE/SIRE)
Como contador responsable de las declaraciones juradas,
quiero que el sistema itere sobre todos los impuestos del catálogo de "Mis Retenciones" (IVA, Ganancias, BS. Personales, etc.) y descargue en Excel los que tengan movimientos en el período,
para consolidar el resumen de retenciones sufridas sin riesgo de omitir ningún impuesto.
US-03Descarga de DDJJ Convenio Multilateral (SIFERE)
Como contador de empresa que tributa en Convenio Multilateral,
quiero que el sistema descargue como PDF cada DDJJ mensual (CM03/CM05) presentada en SIFERE WEB, incluyendo el detalle por jurisdicción provincial,
para archivar digitalmente las constancias de presentación de cada período fiscal.
US-04Descarga de F.931 — Declaración en Línea (SICOSS/SUSS)
Como liquidador de sueldos,
quiero que el sistema extraiga automáticamente los PDF del Formulario 931 de las DDJJ presentadas en un rango de períodos,
para disponer del comprobante oficial de aportes y contribuciones patronales sin navegar manualmente por el portal de AFIP.
US-05Generación de VEP (Volante Electrónico de Pago)
Como responsable de pagos impositivos,
quiero que el sistema complete el wizard de "Generar VEP" en el servicio SETI (Presentación DDJJ y Pagos), con el grupo de impuesto, tipo de pago, período y monto que le indique,
para generar el volante y opcionalmente seleccionar el medio de pago bancario, ahorrando tiempo en el proceso de pago de impuestos.
US-06Autenticación con múltiples representados (Clave Fiscal)
Como contador que gestiona carteras de clientes,
quiero autenticarme con mi CUIT y clave fiscal en ARCA y luego seleccionar el representado correcto antes de ejecutar cada automatización,
para operar en nombre de cada empresa/persona física sin crear sesiones separadas.

2. Flujo Operativo y Secuencia de Automatización

2.1 Mecanismo de Autenticación

  • Lanzar Chromium (modo headed) con anti-detección
    Playwright lanza Chromium con --disable-blink-features=AutomationControlled. Antes de cargar cualquier página se inyecta STEALTH_INIT_SCRIPT vía context.add_init_script(): sobrescribe navigator.webdriver=false, simula plugins de Chrome reales, fija idiomas es-AR y genera un navigator.hardwareConcurrency aleatorio entre 4 y 16.
  • Navegar a https://auth.afip.gob.ar/contribuyente_/login.xhtml
    Se llena #F1\:username con el CUIT, se hace click en #F1\:btnSiguiente (Next), luego se llena #F1\:password con la clave fiscal y se hace click en #F1\:btnIngresar. La sesión queda persistida en las cookies del contexto Playwright.
  • Selección de representado (si aplica)
    _seleccionar_representado() detecta si hay un <select> nativo o una tabla/links/radios con los representados disponibles, selecciona el que coincide con el CUIT del cliente, y espera a que el portal cargue el portal principal.

2.2 Navegación al Servicio

  • Estrategia 1 — Card en Servicios Más Utilizados
    Se busca #serviciosMasUtilizados div[style*='cursor: pointer']:has(h3:text-is('{nombre}')) y se hace click. Cubre los servicios ya pinneados por el usuario.
  • Estrategia 2 — Buscador del portal
    Si no está la card, se activa #buscadorInput, se escribe el nombre del servicio y se clickea li[aria-label='{nombre}'] a.dropdown-item del resultado.
  • Apertura del servicio
    _click_y_esperar_nav() detecta automáticamente si el servicio abre en popup (context.expect_page()) o en la misma pestaña, y devuelve el Page correcto para continuar la automatización.

2.3 Manejo de Errores y Bloqueos

EscenarioComportamiento del sistema
Portal ARCA caído / timeoutPlaywright lanza TimeoutError al no encontrar el selector de login. El runner captura la excepción y emite log ERROR: … con el traceaback. La sesión se marca como fallida.
Captcha / bloqueo anti-botEl script stealth previene la detección. Si ARCA igual bloquea, el contexto queda abierto en modo headed para intervención manual. No hay lógica automática de resolución de captcha.
Cambio de clave fiscal requeridoLa pantalla de login no muestra #F1\:password si el portal fuerza el cambio. El selector falla con timeout y se loggea el error. Requiere intervención manual.
Servicio sin datos en el períodoCada servicio inspecciona el HTML/DOM en busca de mensajes "sin resultados" / "no se encontraron" y lanza _SinDatos o retorna lista vacía, sin interrumpir los demás servicios del job.
Overlays / modales inesperados_dismiss_overlays() itera hasta 8 veces cerrando cualquier modal visible (avisos, tours de onboarding del SETI, novedades).
Descarga no disparadaexpect_download(timeout=60000) lanza excepción si el archivo no llega en 60s; se captura y se loggea como ERROR.

4. Escenarios BDD (Gherkin — Given/When/Then)

Feature: Descarga automatizada de comprobantes ARCA
# Verifica el flujo completo de Mis Comprobantes con dry_run activado

@dry_run @autenticacion
Scenario: Simulación de descarga de comprobantes emitidos (dry_run=true)
Given que el sistema tiene configurado un CUIT válido con clave fiscal
And el parámetro "dry_run" está en true
And el período solicitado es "2026-06-01" a "2026-06-30"
And el tipo de comprobante es "Emitidos" en formato "xlsx"
When se invoca la herramienta "descargar_comprobantes_arca"
Then el sistema NO debe abrir el navegador
And debe retornar un preview con los parámetros validados
And el log debe incluir "[dry_run] Comprobantes Emitidos 2026-06-01 → 2026-06-30 .xlsx"
And ninguna credencial debe aparecer en el output

@autenticacion @navegacion
Scenario: Autenticación exitosa y selección de representado
Given que el portal ARCA está accesible en "https://auth.afip.gob.ar/contribuyente_/login.xhtml"
And el CUIT del contribuyente es un CUIT válido registrado en el sistema
And la clave fiscal es de nivel 3
When Playwright llena el campo "#F1\:username" con el CUIT
And hace click en "#F1\:btnSiguiente"
And llena "#F1\:password" con la clave fiscal
And hace click en "#F1\:btnIngresar"
Then el portal debe redirigir al portal principal de ARCA
And si hay un selector de representados debe aparecer la pantalla de selección
And el script debe seleccionar el CUIT del representado indicado
And el portal debe mostrar el panel de servicios del representado
Feature: Descarga de DDJJ SICOSS (Formulario 931)

@f931 @popup @pdf
Scenario: Descarga exitosa del F.931 para un período con DDJJ presentada
Given que el contribuyente tiene una DDJJ presentada para el período "01/2026"
And el sistema ya está autenticado en ARCA
And el servicio "Declaración en Línea" fue navegado exitosamente
When el script extrae via regex AbrirPopupBorrador('202601','001') del HTML
And ejecuta page.evaluate("AbrirPopupBorrador('202601','001')")
And captura el popup con ctx.expect_page(timeout=15000)
And genera el PDF via CDP Page.printToPDF
Then debe existir el archivo "F931_2026-01_sec001.pdf" en el directorio de descargas
And el archivo debe tener tamaño mayor a 0 bytes
And el log debe contener "OK: F931_2026-01_sec001.pdf"

@f931 @sin_datos
Scenario: Período sin DDJJ presentada — no genera error
Given que el contribuyente NO tiene DDJJ presentada para el período "03/2025"
And el HTML de la pantalla de consulta no contiene llamadas a AbrirPopupBorrador
When se ejecuta el servicio "declaracion_en_linea" con ese rango
Then el sistema debe loggear "Nada para descargar en el rango. Salgo."
And debe retornar una lista de descargas vacía
And NO debe lanzar ninguna excepción
Feature: Generación de VEP — wizard SETI

@vep @wizard @dry_run
Scenario: Creación de VEP IVA mensual con dry_run=true
Given el parámetro dry_run es true
And los parámetros del VEP son grupo="IVA", tipo="Declaración Jurada Mensual", periodo="06/2026", monto=85000.00
When se invoca "generar_vep_arca"
Then el sistema retorna un JSON con los parámetros del VEP a generar
And el campo "estimated_steps" lista los 4 pasos del wizard
And el campo "warning" indica que no se ejecutará ninguna acción real

5.8 Manejo de Popups e iFrames

¿Usa iFrames?

El portal ARCA principal no usa iFrames para los servicios. Los servicios se abren en la misma pestaña o en una ventana popup nueva (nueva pestaña del mismo contexto Playwright).

Popups (nuevas páginas)

  • Declaración en Línea F.931: cada período abre un popup via AbrirPopupBorrador(). Se captura con context.expect_page(timeout=15000).
  • Generar VEP: el paso final de confirmación con medio de pago puede abrir un popup. Se captura igual con context.expect_page(timeout=15000).
  • Mis Comprobantes / SIFERE: navegan en la misma pestaña. _click_y_esperar_nav() detecta automáticamente si hubo popup o navegación same-tab.

CDP Session (Chrome DevTools Protocol)

Para generar PDF sin mostrar el diálogo nativo del SO, todos los servicios que producen PDF usan:

client = context.new_cdp_session(page)
result = client.send("Page.printToPDF", {"printBackground": True, "format": "A4", ...})
pdf_bytes = base64.b64decode(result["data"])
